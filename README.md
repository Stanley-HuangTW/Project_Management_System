# 工作管理平台(MVP)

類似 monday.com 的看板/表格工作管理工具。技術棧:Next.js 16 + TypeScript + PostgreSQL + Prisma。

## 開發環境需求

- Node.js(已安裝於本機:`C:\Program Files\nodejs`)
- PostgreSQL(已安裝於本機:`C:\Program Files\PostgreSQL\17`,service 名稱 `postgresql-x64-17`)
- 資料庫:`hrapp_db`,帳號 `hrapp` / 密碼 `hrapp_dev_pw`(僅本機開發用,見 `.env`)
- Email 通知(選用):在 `.env` 加入以下 SMTP 設定才會實際寄信,沒設定則只會有
  站內通知:
  ```
  SMTP_HOST=smtp.gmail.com
  SMTP_PORT=587
  SMTP_USER=you@example.com
  SMTP_PASSWORD=你的 SMTP 密碼(Gmail 需用「應用程式密碼」,不是登入密碼)
  SMTP_FROM=you@example.com
  ```

## 啟動開發伺服器

```bash
npm run dev
```

開啟 http://localhost:3000,會自動導向 `/login`。

### 預設帳號

- Email: `admin@example.com`
- 密碼: `admin1234`

如需新增更多使用者,可修改 `prisma/seed.ts` 後執行 `npx prisma db seed`,或直接在
`npx prisma studio` 中新增(密碼需用 bcrypt hash)。

## 常用指令

```bash
npm run dev          # 開發伺服器
npm run build        # 正式建置
npm run lint         # ESLint 檢查
npm test             # 執行單元測試(Vitest)
npx prisma studio    # 圖形化檢視/編輯資料庫
npx prisma migrate dev --name <name>   # 修改 schema 後建立新的 migration
```

## 已完成功能(MVP)

- 帳密登入(session cookie,7 天過期)
- 看板清單:新增/重新命名/刪除
- 看板內分組(Group):新增/重新命名/刪除/拖曳排序
- 表格檢視:新增/刪除項目、Inline 編輯儲存格
- 欄位型別:文字、狀態(彩色標籤)、人員、日期、數字
- 看板(Kanban)檢視:依狀態欄位分組顯示,拖曳卡片可改變狀態;可拖曳空白處
  平移橫向捲動(同甘特圖),頂部另有一條同步捲動軸方便快速拖曳;主管檢視時
  可切換只看自己團隊/全部的卡片
- 項目子項目(subitem):任一項目可新增子項目,支援多層巢狀、展開/收合,
  刪除父項目會連帶刪除子項目
- 從 Excel/CSV 匯入工作事項:表格右上角「匯入」按鈕開啟精靈,支援上傳
  .csv/.xlsx/.xls 檔案,或貼上公開分享的 Google Sheet 連結(需設定為「知道
  連結的使用者」可檢視,否則會顯示錯誤訊息並建議改用上傳檔案)。可選擇要
  匯入的工作表、標題列、以及每一欄要對應成「項目名稱」「階層層級(建立子
  項目)」「現有欄位」或「新增欄位」。狀態欄位若遇到未知的標籤文字會自動
  新增對應的彩色選項。
- 項目留言:每個項目列旁的留言圖示可開啟留言串,多人可在項目下討論
- 站內通知:側邊欄使用者名稱旁的鈴鐺圖示,會在以下情況通知相關人員(指派人員 +
  board 擁有者,不含自己觸發的變動,每 30 秒自動更新未讀數):
  - 人員欄位新增指派某人時,通知被指派的人
  - 項目的狀態/數字/文字等欄位有變動時,通知該項目所有已指派的人
  - 有人在項目下留言時,通知該項目所有已指派的人
- 子項目進度自動彙總到父項目:看板可指定一個數字欄位當「進度欄位」,有子項目的
  項目會自動顯示子項目進度的遞迴平均值(唯讀),不需手動填寫
- 任意位置新增項目:每一列的操作選單可選「上方插入項目」「下方插入項目」,
  不限於在群組最後新增
- 資源分配甘特圖:看板檢視新增「甘特圖」分頁,可指定「開始日期欄位」與「天數
  欄位」畫出時間軸;每個任務可指派多人,各自設定佔用當天工作量的固定百分比
  (整段任務期間不變);底部「人員負載」列會依每人每天的分配總和標示是否超過
  100%(過載)
- 儀表板:側邊欄「儀表板」連結,跨所有看板彙總 ——
  團隊工作量總覽(依甘特圖欄位設定計算每人日/週/月分配總和)、成員工作量明細
  (各成員獨立卡片:指派任務清單與佔比、每週甘特圖時間軸含月份標示、每月人月
  工時使用率,三段顏色門檻可由管理者調整百分比與顏色)、看板進度總覽(各看板
  項目數/狀態分布/平均進度)、逾期與 7 天內即將到期項目、看板篩選、我的項目
  與(主管視角)團隊項目(指派給目前登入者或團隊成員,含透過人員欄位或甘特圖
  人員分配兩種方式);成員工作量明細展開後,主管/管理者可對自己團隊成員「新增
  任務」——從自己目前被指派的任務中選一個當父任務,在週時間軸點選起始/結束週
  設定日期(整週為單位,天數 = 週數 x 7),預設分配 100% 給該團隊成員,建立為該
  父任務的子項目(需看板已設定甘特圖「開始日期」與「天數」欄位)
- 三級角色權限:管理者/主管/團隊成員。主管可派工與新增/刪除任務,團隊成員只能
  更新狀態/進度與留言;管理者權限最高,可管理使用者帳號、匯入匯出、看板結構
- 使用者管理頁面:管理者可新增帳號、設定角色、指定所屬主管(建立主管-團隊階層,
  用於範圍限定甘特圖指派與儀表板)、上傳每個帳號的大頭貼照片(自動壓縮成小圖存
  於資料庫,不需另外設定檔案儲存服務);可編輯既有帳號的姓名/Email/角色、拖曳
  排序調整帳號顯示順序、刪除帳號(擁有看板或已留言/上傳檔案的帳號需先移轉或
  清空才能刪除,且系統會保留至少一位管理者、不可刪除自己)
- 人員指派改為大頭貼選單(仿 monday.com):「負責人」欄位與甘特圖「人員分配」
  彈窗都改成點開後以照片(或無照片時的顏色姓名縮寫)列出可指派對象,點選即完成
  指派
- Resource 欄位批次對應到帳號、表格內直接指派任務(不需先設定甘特圖日期)
- 表格檢視:欄位可拖曳調整順序(項目名稱固定於最前)、項目名稱欄位可拖曳調整
  寬度(預設寬度自動依最長項目名稱撐開,上限 400px 避免佔滿畫面擠壓其他欄位,
  需要看完整名稱可再手動拖寬)、通用篩選列(依任一欄位篩選)、項目名稱欄位
  凍結不隨橫向捲動移動、表格外框加粗框線;可在「階層顏色」設定每個巢狀階層
  (Lv 1~6)的整列底色,方便一眼分辨階層深度
- 甘特圖:凍結項目名稱欄、可拖曳平移時間軸;開始日期/天數/結束日期三者填寫其
  二會自動算出第三個(以工作日計算,週六日不計入天數)
- 前置依賴(Pred/Link)欄位:依匯入的 WBS 前置依賴文字與日期,自動判斷並寫入
  FS(完成到開始)/FF(完成到完成)/SS(開始到開始)/SF(開始到完成)關聯類型,
  前置依賴或日期異動時自動重新計算
- 自動化規則引擎:狀態欄位變更為指定值時,可組合觸發「通知特定人」「自動設定
  另一個欄位的值」「自動移動到別的分組」
- Board 層級權限/分享設定:每個看板預設「公開」(所有登入使用者可存取),看板
  擁有者或管理者可改為「限制」,只有擁有者、管理者與指定成員可看到/進入該看板
  (從側邊欄清單、儀表板到直接輸入網址都會擋下);限制後仍沿用既有的全域角色
  權限決定能做什麼
- Email 通知:設定 `.env` 的 SMTP 資訊後,「指派」與「自動化規則」通知會額外
  寄送 Email(狀態更新、留言等站內通知不會寄信);未設定 SMTP 時自動略過,不
  影響原有站內通知
- 項目詳情視窗(仿 monday.com):點項目的留言圖示開啟,分五個分頁——
  「更新」(留言動態牆,含大頭貼與時間)、「檔案」(上傳/下載/刪除附件,存於
  伺服器本機 `public/uploads/`,不需另外設定雲端儲存)、「活動紀錄」(自動記錄
  欄位變更、人員指派、留言、上傳檔案、待辦事項異動等歷史)、「項目卡片」(該
  項目所有欄位的卡片式總覽,含待辦事項完成度)、「待辦事項」(子任務清單,可
  勾選完成/取消完成,完成會加上刪除線;僅顯示進度,不會限制項目狀態能否改成
  已完成)
- 看板報表(仿 monday.com Dashboard):看板檢視新增「報表」分頁,顯示全部/尚未
  處理/計畫中/進行中/暫停/卡住/已完成計數卡、依狀態分布圓餅圖、依負責人分布
  長條圖、逾期任務清單;可在「報表設定」指定要統計的狀態欄位、以及每個狀態
  選項屬於哪個分類(未指定的算進行中);主管檢視時預設只看自己團隊的資料,
  可切換看全部
- 匯出 Google Sheet(Gantt):看板工具列「匯出」按鈕,選擇一個分組即可下載
  完整的 .xlsx 範本(Settings/Lists/Gantt Day·Week·Month 五個分頁,含甘特
  條、階層顏色、下拉選單、Week/Month 皆為參照 Day 的公式),以及一份 Apps
  Script(.gs)範本檔;上傳 .xlsx 到 Google 雲端硬碟並以「Google 試算表」開啟
  即可直接使用,第一次需在該試算表的「擴充功能 → Apps Script」貼上下載的
  .gs 內容並儲存,即可使用「Gantt」選單的所有功能(此功能無法直接建立雲端上
  的 Google 試算表檔案,因為那需要 Google API 授權,目前尚未串接)

### 第一梯:排程引擎的洞(核心用途,缺這些會直接影響決策)

- [x] **基準線(Baseline)/計畫 vs 實際** — 已完成
  系統設定 →「基準線(Baseline)」可為每個看板建立/重新建立/清除。建立後,甘特圖
  每根長條下方會畫出當初的計畫(灰色細條),項目卡片會顯示基準線區間與「延遲 N 天 /
  提前 N 天 / 準時」。差異用日曆天計算(週末造成的落後不會被少算)。
  排程永遠不會再動到這份快照——這正是重點:實際日期在移動時,計畫必須待著不動,
  「我們落後多少」才有答案。後續的 S-curve、SPI 都建立在它上面。
- [x] **一個任務只能有一個前置** — 已完成
  Pred 改存逗號分隔的 id 清單(`12,15`,MS Project 的寫法),排程取「把這個項目
  推得最晚」的那一個前置。多個前置共用該項目自己的 Link 與 Lag——每條邊各自的
  關係型別得寫進 Pred 欄位本身,那不是 Link/Lag 欄位在這裡的意思,算是已知限制。
- [x] **要徑(Critical Path)與浮時(Total Float)** — 已完成
  甘特圖工具列的「要徑」按鈕會標出總浮時為 0 的工作項(紅框),按鈕上顯示目前
  有幾項;滑鼠停在長條上會說明這一項的浮時、最晚可完成日,已落後的會直接說落後
  幾天。項目卡片也有「總浮時」欄位。只算葉節點——Summary 的日期是子項統計出來
  的,再給它自己的浮時等於重複計算。
  註:目前的 `Priority = CRITICAL` 是人工標的標籤,和這個算出來的要徑無關。
- [x] **日期約束(Constraints)** — 已完成
  項目卡片的「日期約束」欄位,三種型別各自的行為刻意不同:
  「不得早於(開始)」前置算出的開始日太早時把項目往後推;「必須完成於」把完成日
  釘住、開始日往回推算(會把項目往前拉,它是固定日期不是下限);
  「不得晚於(完成)」**不會**改動排程——期限不會讓工作變快,超過時是要回報的事實,
  偷偷把項目往前拉只會弄壞它的前置、順便把問題藏起來。設定後會連動重算下游。
- [x] **甘特圖畫出相依箭頭** — 已完成
  工具列的「相依箭頭」按鈕(預設開啟)會在長條之間畫出前置依賴,FS/SS/FF/SF 各自
  連到該關係指名的兩端;停留在箭頭上會顯示「前置 → 後續(關係)」。要徑上的箭頭
  (兩端都在要徑上)會跟著標紅。長條位置是量測 DOM 得到的,所以收合、篩選、顯示
  比例縮放都會跟著對位;有一端不在畫面上的連線就不畫。

### 第三梯:日常操作(成本低、每天有感)

- [x] **批次編輯** — 已完成
  表格每列左邊多一個勾選框,勾了之後上方出現批次列:可一次設定任一個狀態欄位
  (Type/Priority/Status/Link…)、任一個人員欄位,或把整批時程往後/往前推 N 天
  (負數表示提前)。權限是逐項檢查而不是整批一次——MEMBER 只能改指派給自己的項目,
  批次編輯不該變成繞過它的路;不符合的項目會被跳過並回報數量與原因,
  不會因為一列不合格就讓其他 199 列全部失敗。
- [x] **@提及** — 留言打 `@` 會跳出成員選單,送出後被提及的人收到「在某項目的留言中提到你」的通知(不會再收到同一則留言的一般通知),留言裡的名字以底色標出。
- [x] **儲存的檢視** — 篩選條件設好之後可以存成具名檢視(表格與甘特圖共用),下次從下拉選單
  一鍵套用,也可以「更新為目前條件」或共用給看板成員。日期篩選多了「今天」這個選項——
  存成檢視的是「今天」而不是存檔當天的日期,所以「我的逾期任務」明天看還是逾期任務。
- [x] **垃圾桶/復原** — 刪除改為軟刪除(`Item.deletedAt`),項目連同子項目進垃圾桶,
  留言、檔案與歷史紀錄都還在;從看板「…」選單的垃圾桶可以還原或永久刪除。還原會一併
  還原跟著刪掉的子項目、把刪除時被改寫的下游 Pred 放回去(刪除時已存成 `deletedPredSnapshot`),
  並把父項的 Type 改回 Summary。所有讀取路徑(看板、排程引擎、儀表板、報表、批次編輯)
  一律過濾 `deletedAt: null`,垃圾桶裡的項目不會再參與排程或出現在任何統計。
- [x] **專案範本** — 把一個已經排好的分組存成範本(看板「…」選單 →「專案範本」),
  下個專案挑範本、挑分組、挑起始日期就建出整個階段結構。範本只帶結構:名稱、階層、
  Type/Lvl、天數與前置關係;負責人、狀態、% 完成與日期都不帶——那些屬於上一次的專案。
  欄位以「名稱+型別」對應而不是 id,前置關係以範本內的位置記錄,所以範本可以跨看板套用。
  日期完全由起始日期加上範本裡的天數與前置關係算出。

### 第四梯:報表與治理

- [x] **S-curve / 燃盡圖** — 報表頁的「進度曲線」:計畫(基準線)、目前排程、實際完成三條
  累計曲線,可切換成燃盡圖(看剩下多少)。以葉節點工作項數量計算(Summary 的日期是子項統計
  來的,再算一次等於重複計算),每週一點。「實際完成」以已完成工作項的結束日期認列,
  且只畫到今天——畫到未來就變成預測了,那是「目前排程」那條線在做的事。
- [x] **風險與議題登錄簿** — 看板多一個「風險」檢視:機率×衝擊(各 1-5,分數 1-25 依
  5×5 矩陣分成低/中/高/極高並上色)、對策、負責人、對策到期日、相關工作項。清單依分數排序,

## 正式部署(Docker Compose)

需要 Docker 與 Docker Compose。部署到內部伺服器的步驟:

1. 複製環境變數範本並填入真實值:
   ```bash
   cp .env.production.example .env.production
   ```
   編輯 `.env.production`,至少要設定 `POSTGRES_PASSWORD`、`AUTH_SECRET`(用
   `openssl rand -base64 32` 產生)、`APP_BASE_URL`(這台伺服器對外的真實網址,
   密碼重設信件連結與 Google OAuth 都會用到)。SMTP/Google OAuth 是選用的,
   沒填就只會停用信件通知/Google Sheet 私人帳號登入匯入。

2. 建置並啟動(`-p hrapp` 是明確指定專案名稱,避免專案資料夾路徑含中文字或
   特殊字元時,Docker Compose 從資料夾名稱推導專案名稱失敗而報
   `project name must not be empty`):
   ```bash
   docker compose -p hrapp --env-file .env.production up -d --build
   ```
   第一次啟動時,`app` 容器會先執行 `prisma migrate deploy` 套用資料庫結構,
   再啟動伺服器。PostgreSQL 資料與上傳的附件檔案分別存在 `db_data`、
   `uploads_data` 這兩個 Docker volume,重啟/更新容器不會遺失。

3. 開啟 `http://<伺服器位址>:3000`。首次啟動資料庫是空的,沒有任何使用者,
   需要先建立管理員帳號才能登入,可執行:
   ```bash
   docker compose -p hrapp exec app npx prisma db seed
   ```
   會建立 `admin@example.com` / `admin1234`,登入後記得立刻改密碼。

之後要更新版本,`git pull` 後重新執行第 2 步的指令即可(會自動重新 build
image 並套用新的資料庫 migration)。
