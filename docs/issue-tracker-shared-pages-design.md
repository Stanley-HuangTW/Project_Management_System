# ISSUE TRACKER 納入共用功能的設計(待使用者確認,尚未動程式)

需求:使用者管理、組織架構圖、系統設定、工時、使用者回報、使用手冊,在 ISSUE TRACKER 裡也要有;使用者管理與組織架構圖是**同一份資料**。

## 一、做法:網址加 /issues 前綴,頁面元件共用

目前這些頁面都在專案管理系統的 `(dashboard)` 外框底下(外框會檢查「能不能進專案管理系統」並放看板側邊欄),只能進 ISSUE TRACKER 的人進不去。做法:

| ISSUE TRACKER 網址 | 內容 | 與專案管理系統的關係 |
|---|---|---|
| `/issues/users` | 使用者管理 | 同一個頁面元件、同一份 User 資料 |
| `/issues/org-chart` | 組織架構圖 | 同一個頁面元件、同一棵 OrgNode 樹 |
| `/issues/timesheet` | 工時 | 同一個頁面元件、同一批工時資料與工時類別 |
| `/issues/feedback` | 使用者回報 | 同一份 UserFeedback(已有「系統」欄可分流) |
| `/issues/manual` | 使用手冊 | 同一份手冊 |
| `/issues/settings` | 系統設定 | **獨立一頁**(見第三節),只放 ISSUE TRACKER 與共用的設定卡片 |

為什麼用網址前綴、不用「記住上次在哪個系統」的 cookie:網址就說明現在在哪個系統,側邊欄、權限、「?」對應的手冊章節都不用猜;書籤也不會因為上次用哪個系統而變樣。代價:共用元件裡少數幾個寫死的連結(例如使用者管理頁籤的 `/users?tab=leave`、手冊連結 `/manual#…`)要改成跟著系統走,大約 6 處。

**不複製資料表。** 這些頁面本來就只有一份資料,新增的只是「從 ISSUE TRACKER 側邊欄走進去的另一個網址」。

## 二、ISSUE TRACKER 側邊欄(同一套風格,只放相關與共用的)

案件列表 ・ 回報新案件 ・ 我的案件 ・ 各產品統整 ・ **工時** ・ **系統設定**(底下:使用者管理、組織架構圖、ISSUE TRACKER 設定)・ 選項管理 / 匯入(管理者)・ **使用者回報**(管理者,未處理數徽章)・ **使用手冊**
底部:使用者、切換到專案管理系統、登出(同現在)。不放看板、儀表板、週報、待我審核、對話、更新記錄、資料備份。

## 三、各項怎麼設計

**1. 使用者管理 / 組織架構圖**:頁面與權限沿用現有(使用者管理只有系統管理員;組織架構圖大家可看、管理員可編)。ISSUE TRACKER 的角色(回報人 / 處理人 / 管理者)與「可進哪個系統」本來就在使用者管理裡設定,不另外做。→ **問題 A**:ISSUE TRACKER 的「管理者」(非系統管理員)要不要也能指派別人的 ISSUE TRACKER 角色?

**2. 系統設定**:不直接共用現有那一頁,因為它是一整張專案管理專屬的設定(甘特圖、週報排程、BOM 預設欄位、預算、Mantis…),只能進 ISSUE TRACKER 的人不該看到或改到。`/issues/settings` 只放:
- ISSUE TRACKER 專屬:處理天數(工作天 / 日曆天)、指派時寄信、(之後:SLA、預設歸屬規則)
- 共用、兩邊都影響的:Email 通知總開關與通知類型、公司假日(處理天數的工作天用它)、工時類別、組織單位
- 不放:甘特圖、週報、BOM、預算、Mantis、階層顏色、磁碟與備份(整套系統的設定,仍在專案管理系統的系統設定)
這些卡片現在寫在同一個大檔案裡,要拆成可單獨引用的元件(內容不變);兩邊改的是同一筆設定資料。誰能改:系統管理員。→ **問題 B**。

**3. 工時**:沿用現有工時,不做第二套。現有的工時有兩種:專案工時(登記在看板工作項,要主管核准)與非專案工時(登記在「工時類別」,可連結風險議題或對應專案,登記即生效)。ISSUE TRACKER 的案件工時屬於後者,做法:
- 非專案工時多一個「**連結案件**」(跟「連結風險議題」同一個做法,案件刪掉只是斷開連結);工時類別多一個「可連結案件」的開關,登記時選案件。只能進 ISSUE TRACKER 的人在工時頁看到的就是這種(他沒有看板,專案工時那一塊自然是空的)。
- 案件頁多一塊「**花費工時**」:累計小時數、誰什麼時候登記了多少,並有「登記工時」快捷鈕(自動帶案件);列表與統整頁新增「平均每案花費工時」。這樣「ISSUE 解決花費時間」就有兩個數字:**處理天數**(從發生到結案)與**花費工時**(實際投入的人時)。
- 登記即生效,不走主管核准(跟現有非專案工時一致)。
- → **問題 C、D、E**。

**4. 使用者回報**:上一則已做好(`7c6bdfd`):每則標明來自專案管理系統 / ISSUE TRACKER / 登入選系統頁,可篩選。這次只是把「使用者回報」頁也掛到 ISSUE TRACKER 側邊欄(`/issues/feedback`,管理者,含未處理數徽章)。

**5. 使用手冊**:`/issues/manual` 同一份手冊,「?」在 ISSUE TRACKER 裡開的連結改成 `/issues/manual#…`,留在 ISSUE TRACKER 外框裡。第 24 章已有。→ **問題 F**。

## 四、實作階段(確認後)
1. 外框與側邊欄、`/issues/users`、`/issues/org-chart`、`/issues/feedback`、`/issues/manual`、`/issues/timesheet`(共用連結改成跟著系統走)。
2. 系統設定拆卡片 + `/issues/settings`。
3. 工時連結案件:資料表(ActivityTimeEntry 加 issueCaseId、TimeCategory 加 linkIssueCase,純新增)、工時登記視窗、案件頁花費工時、統整頁平均工時。
4. 手冊補章節、helpTopics 補對應、測試、docker build、示範環境驗證。

## 五、請您回答(沒回答就採「預設」)
- **A** ISSUE TRACKER 管理者(非系統管理員)能不能指派別人的 ISSUE TRACKER 角色?*預設:不能,只有系統管理員(使用者管理本來就是管理員專用,內含薪資與密碼等欄位)。*
- **B** ISSUE TRACKER 的管理者(非系統管理員)能不能進 `/issues/settings` 改 ISSUE TRACKER 專屬設定(處理天數、指派寄信)?共用的(Email、假日、工時類別)是否只有系統管理員?*預設:專屬設定管理者可改,共用設定只有系統管理員可改。*
- **C** 工時類別要不要預設新增「客服維修處理」之類、並開啟「可連結案件」?*預設:新增一個「案件處理」類別並開啟連結案件;原有類別不動。*
- **D** 誰看得到案件上別人登記的工時?*預設:案件的累計小時與明細,ISSUE TRACKER 的管理者與負責人看得到;其他人只看得到自己登記的(沿用現有「看得到誰的工時」規則)。*
- **E** 專案管理系統的工時頁要不要也能把工時連到案件?*預設:要,同一個登記視窗,類別開了「可連結案件」就能選(兩邊一致)。*
- **F** 只能進 ISSUE TRACKER 的人看使用手冊,要看全部章節還是只看相關章節(登入、說明與回報、工時、組織架構、ISSUE TRACKER)?*預設:全部章節,不做過濾。*
- **G** 側邊欄的「系統設定」底下放使用者管理、組織架構圖(跟專案管理系統一樣)可以嗎?*預設:可以。*
