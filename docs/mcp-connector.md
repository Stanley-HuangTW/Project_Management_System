# MCP 連接器

讓 Claude（或任何支援 MCP 的用戶端）直接查這套系統的資料，不必人工複製貼上。

## 這不是第三方連接器

Slack、Notion 那種是廠商自己做了端點放進 Claude 的目錄裡。這套是自架系統，目錄裡不會有 —— 所以是自己做的一個，端點就長在這個 app 裡。

## 一、產生金鑰

**系統設定 → 整合 → 新增 API 金鑰**。

金鑰只在產生的當下顯示一次，之後資料庫裡只有雜湊值，連這個 app 自己都讀不回來。抄下來貼進設定檔，不要貼進聊天視窗。

金鑰**沒有自己的權限**，它借用發金鑰那個人的。所以：

- 用 MEMBER 的帳號發的金鑰，看得到的看板就跟那個人登入時一樣
- `run_sql` 只接受 **ADMIN** 的金鑰

## 二、接上 Claude Code

`~/.claude.json`（或專案的 `.mcp.json`）：

```json
{
  "mcpServers": {
    "工作管理平台": {
      "type": "http",
      "url": "https://你的網址/api/mcp",
      "headers": { "Authorization": "Bearer ${HRAPP_API_KEY}" }
    }
  }
}
```

金鑰放環境變數 `HRAPP_API_KEY`，不要寫死在檔案裡 —— 設定檔常常會進版控。

接上之後用 `/mcp` 確認連線狀態。

## 二之二、接上 Cowork / claude.ai(OAuth)

Claude Code 用金鑰就夠了,但 **Cowork 與 claude.ai 的自訂連接器走 OAuth**,而且是從 Anthropic 的雲端連過來的 —— 不是從你這台電腦。兩個結果:

- **端點必須對外開放**(正式網域 + HTTPS)。只在 localhost 或內網跑的話,那邊連不到,這條路不通。
- **不用手動貼 token**,使用者按「允許」就完成授權。

這個 app 已經實作了整套所需的端點:

| 端點 | 做什麼 |
|---|---|
| `/.well-known/oauth-protected-resource` | 告訴用戶端該找哪台授權伺服器(RFC 9728) |
| `/.well-known/oauth-authorization-server` | 授權伺服器的自我描述(RFC 8414) |
| `/api/oauth/register` | 動態註冊(RFC 7591),用戶端自己登記,不用有人開後台 |
| `/oauth/authorize` | 同意畫面,人在這裡按允許 |
| `/api/oauth/token` | 換權杖與更新權杖 |

設定步驟:claude.ai → **Settings → Connectors → Add custom connector**,網址填 `https://你的網域/api/mcp`,其餘留空 —— 註冊與授權會自己跑完。

### 這一層守了什麼

- **強制 PKCE,而且只收 S256**。`plain` 的 code_challenge 就是 verifier 本身,攔到授權請求的人直接就有 verifier,等於沒做 —— 所以不收。
- **redirect_uri 必須跟註冊的完全相同**。前綴比對會讓 `https://claude.ai.evil.com/cb` 這種東西通過,授權碼就送到別人手上了。
- **授權碼一次性,活 60 秒**。用第二次不只是拒絕,**連同那張碼換出去的權杖一起撤銷** —— 一張碼被用兩次代表它很可能被攔截了,這時候保住資料比保住連線重要。
- **更新權杖也是一次性的**,換一次就輪替。
- **授權碼與權杖都只存雜湊**,外流的備份裡沒有能用的東西。
- **不發 client_secret**。MCP 的用戶端是公開用戶端,密鑰藏不住,保護來自 PKCE 與 redirect_uri 比對,不靠一個會外流的密鑰。
- **權杖借用授權那個人的權限**,而且角色是每次查的 —— 一個人被降權之後,他先前發出去的權杖立刻跟著降。

### 撤銷

**系統設定 → 整合 → 已授權的 MCP 應用程式**,按垃圾桶,那個應用程式手上的權杖立刻全部失效。


## 三、有哪些工具

| 工具 | 回答什麼 |
|---|---|
| `list_boards` | 有哪些看板、屬於哪個專案群組、有哪些分組與欄位 |
| `list_items` | 一個看板的工作項：WBS、名稱、負責人、起訖日、狀態 |
| `search_items` | 跨看板搜尋工作項名稱 |
| `list_overdue` | 逾期、七天內到期、已完成 |
| `get_critical_path` | 要徑（同一個專案群組的看板一起算） |
| `get_delay_analysis` | 整體晚幾天、哪些工作項是自己延誤的 |
| `get_budget` | 一個階段的核准／已花費／已下單／剩餘、是否超支 |
| `get_labour_sheet` | 人力表：逐月投入、各單位人月與金額、階段差異 |
| `get_proto_plan` | 樣機計畫：產品 × 用途 × 階段;另外列出每一台樣機,以及哪些工作項在用它(起訖日、佔用百分比),沒人在用的是空的 |
| `get_workload` | 每個人被指派了什麼、負載多少 |
| `get_org_chart` | 角色、單位、主管、階層、下轄人數 |
| `run_sql` | 唯讀 SQL（僅管理者） |

大部分工具要 `boardId`，先用 `list_boards` 拿。

**計算一律重用畫面在用的那些函式**，不另外寫一套 —— 報表上的數字跟這裡問到的必須是同一個，否則兩邊對不起來的時候沒人知道該信哪一個。

## 四、`run_sql` 的限制

這支工具**刻意繞過應用層的所有權限檢查**。那是它的用途（跨看板統計、稽核），也是它的風險。所以：

- **只有 ADMIN 的金鑰能用**
- 只允許**單一句** `SELECT` 或 `WITH`
- 最多回 **1000 列**（沒寫 `LIMIT` 就自動補上）
- **每一次通過閘門的查詢都寫進稽核軌跡**（系統設定 → 稽核軌跡，搜尋 `MCP run_sql`），先記錄再執行，所以查詢失敗也留得下來
- 擋掉：任何寫入動詞、`SELECT ... INTO`、`set_config` 這類改狀態的函式、讀伺服器檔案的 `pg_read_*`、連外的 `dblink` / `postgres_fdw`、分號串接

閘門採白名單而不是黑名單。黑名單擋關鍵字在 SQL 上一向擋不乾淨（註解、大小寫、字串裡的字都能繞），白名單的失敗方向是「把合法查詢擋下來」—— 那是安全的失敗方向。錢字號引號與反斜線跳脫的 E 字串一律拒絕不解析，這樣閘門看到的分隔符只會比 Postgres 多、不會少。

資料表名稱是大寫開頭且**要加雙引號**：`"Board"`、`"Item"`、`"CellValue"`、`"Budget"`。

## 五、把端點對外開放之前

這個端點目前跟 app 一起跑。要讓 Cowork 或別台機器連得到，就得對外暴露，那是另一個風險等級：

- **一定要 HTTPS**。金鑰是 Bearer token，明文 HTTP 等於把它公開
- **考慮限制來源 IP**，只開給需要的網段
- **金鑰外流等於整個資料庫外流**（如果那是 ADMIN 的金鑰）。定期在整合頁面看 `lastUsedAt`，不用的就刪掉
- 只需要唯讀統計的話，**發一把 MEMBER 或 SUPERVISOR 的金鑰就好** —— 它拿不到 `run_sql`，看得到的看板也受限

只有自己這台機器要用的話,不必對外開放:Claude Code 直接用 API 金鑰打 `http://localhost:3000/api/mcp` 就好,金鑰不離開這台機器。

**要讓 Cowork / claude.ai 用得到就一定得對外開放**,沒有別條路 —— 那邊是從 Anthropic 的雲端連過來的。要開的話:

- 用 **Cloudflare Tunnel** 之類的方式,不必在防火牆上開埠、也不需要固定 IP(通道是從你這邊撥出去的)
- `APP_BASE_URL` 要改成對外的網址 —— OAuth 的自我描述與導向都照它產生,還留著 localhost 的話整套談不起來
- 對外之後,**登入頁與所有 API 也一起暴露了**。密碼鎖定機制本來就在,但值得再看一次誰有帳號
- 想只給週報、不想開整套,見 [weekly-report.md](weekly-report.md):那條路一個洞都不用開

## 六、除錯

用瀏覽器打開 `https://你的網址/api/mcp`（GET，不需金鑰）會回一段自我描述與工具清單 —— 可以先確認端點活著、路由沒接錯。

`401` 幾乎都是金鑰沒帶或帶錯格式，標頭要長這樣：`Authorization: Bearer hrapp_...`。
