## 1. 認識 ISSUE TRACKER

ISSUE TRACKER 用來記錄客戶回報的維修與問題(原本記在 Google Sheet「客服維修紀錄」):回報問題、判斷歸誰處理、依 Sales → FAE → RD 的流程往下走、寫下解決方案與進度、需要時簽核、算處理花了幾天,以及統整**哪個產品最容易發生什麼問題**。它跟專案管理系統**共用帳號與網址**,網址是 `/issues`。

### 1.1 進入與切換系統

- 管理者在「使用者管理」決定每個人能進哪個系統。**只能進 ISSUE TRACKER** 的人,登入後直接進案件列表;**兩個系統都能進**的人,登入後先看到「選擇要進入的系統」;兩個都不能進的人會看到「尚未被授權」,請找系統管理員。
- 進去之後,可以從**左下角使用者選單的「切換到專案管理系統」**換過去(只有兩邊都能進的人看得到);使用者選單裡也有個人資料與登出。
- 側邊欄的鈴鐺是**通知**:被指派、輪到你處理、等你簽核、簽核結果、卡關提醒都會出現在這裡,點一則會直接開到對應的案件或簽核頁。

### 1.2 角色

每個人在 ISSUE TRACKER 有一個**權限角色**,決定能改什麼:

| 角色 | 能做什麼 |
|---|---|
| 回報人 | 回報新案件;修改**自己回報、還沒鎖定**的案件的回報內容;在時間軸留言、上傳附件;看得到案件的流程進度(不能推進階段) |
| 處理人 | 回報人能做的,加上修改**自己負責或還沒人負責**的案件的處理內容(狀態、問題類型、更換零件、RMA…);可以「接手」沒人負責的案件 |
| 管理者 | 所有案件都能改(包括已鎖定的)、指派負責人、解除鎖定、刪除案件、管理選項、匯入 Excel。系統管理員自動是管理者 |

另外每個人還可以有**客服維修流程角色**:**Sales / FAE / RD**(可複選)。它管「輪到誰、通知誰」,不影響能改什麼(見第 4 章)。兩種角色都由系統管理員在「使用者管理」設定(11.1)。

### 1.3 側邊欄

案件列表、回報新案件、我的案件、各產品統整、工時、**待我簽核**(旁邊的數字是等你簽的張數)、「系統設定」群組(使用者管理、組織架構圖、ISSUE TRACKER 設定)、選項管理 / 匯入【管理者】、使用者回報【系統管理員】、使用手冊。窄螢幕時側邊欄變成上方一列。

## 2. 回報新案件

左側「回報新案件」。必填:**客戶、產品型號、發生日期**;**維修(Repair)**案件還要填機器的 QR code 或序號;**問題(Issue)**案件要填問題描述。客戶、產品型號、地區、保固狀態、問題類型、更換零件、處理單位都是下拉選單,選項由管理者在「選項管理」維護(第 9 章)。

送出時系統**自動產生案件編號**:`CS` + 發生日期(西元年月日)+ `-` + 當月流水號,例如 `CS20260106-001`。流水號依「發生日期所在的月份」每月從 001 起算;編號是**唯一**的——就算好幾個人同時回報也不會重號,而且建立後不再改變(改發生日期、刪除案件都不會讓編號重複使用)。

回報人只填「回報內容」;「處理內容」(狀態、負責人、問題類型、零件、RMA、機器時數…)由處理人或管理者填。處理人自己新增的案件,預設就是自己負責。管理者和處理人新增時,可以勾「同時建立到 Mantis」(第 8 章)。

新案件一送出,FAE 與管理者會收到通知(4.5)。

## 3. 案件頁

點案件列表的案件編號進來。最上面是案件編號、狀態、優先級與處理天數,下面是**流程進度條**(第 4 章),再往下左邊是表單、右邊是時間軸、簽核、Mantis、花費工時與附件。

- **歸屬**:負責人(可以多人)與處理單位(可以多個,例如 HW 與 QA)。負責人由管理者指派,被指派的人會收到站內通知(系統設定可以另外寄 email);處理人可以按「接手」把沒人負責的案件變成自己負責。
- **問題類型**:名稱開頭的代碼就是大類——SW 軟體、HW 硬體、CN 查無問題 / 操作、LM 設計限制、OP 安裝 / 操作錯誤。
- **狀態**:處理中 → **暫時解決(TC)** 或 **永久解決(PC)**(也可標「不適用 NA」)。改成暫時 / 永久解決時,沒填結案日期會自動帶今天;改回處理中會清掉結案日期。狀態、優先級的變更會自動記進時間軸。**狀態**看「解決了沒」,跟流程階段(輪到誰)是兩件事。
- **進度與解決方案時間軸**:可以逐筆新增「回應 / 分析」「處理安排」「解決方案」「備註」,每一筆都記得是誰、什麼時候寫的;流程階段的推進、簽核、轉維修也會自動記一筆「流程」。第一筆回應、安排或解決方案的時間,就是「首次回覆時間」。
- **更換重要零件**:可以選任意多個(原 Sheet 最多 7 個),**RMA** 與 **RMA By Cutting Disk** 勾選,另有維修單號。
- **機器計數**:刀盤升降次數、割草時數、行走時數是機器端的計數器(不是處理花的時間)。
- **附件與連結**:可以上傳檔案(照片、影片、PDF…,單檔 50 MB),也可以貼外部連結(例如 Google Drive 影片,只收 http / https)。

## 4. 客服維修流程

案件依「URS 客服維修紀錄流程」圖走,每件案件有一個**流程階段**,案件頁最上面是進度條,列表也有「階段」篩選。階段看「走到哪、輪到誰」,跟狀態(處理中 / TC / PC)是兩件事。

### 4.1 流程角色與階段

**流程角色**:系統管理員在「使用者管理」編輯使用者時,可以勾 **Sales / FAE / RD**(可複選)。輪到某個階段時,通知那個角色的人;只有**該階段輪到的角色、案件負責人、管理者**能推進階段(回報人只能看)。還沒設定任何流程角色的團隊也能用——案件負責人就能推進。

**問題(Issue)線**:已通報 → FAE 評估 →(需要 RD 協助就到 RD 處理中,RD 處理完回 FAE 評估)→ 待 Sales 判斷 → 結案簽核中 → 已結案;待 Sales 判斷也可以「回到已通報」繼續處理,或申請轉維修。FAE 評估完自己能處理(聯繫客戶、安排外勤)的,可以直接結案。

**維修(Repair)線**:已通報 / FAE 評估 → 運送中 → 已收件(配件清點)→ 維修中 → 維修完成 → 結案簽核中 → 已結案。FAE 評估直接到維修中 = **現場更換**(不用送回);客戶自己送來的件,可以從已通報直接收件。

進度條旁的按鈕可以往下一階,或**退回**前面的階段;每一次都記進時間軸。簽核進行中的案件不能改階段。

**建立到 Mantis = 請 RD 協助**:問題案件在「已通報」或「FAE 評估」按「建立到 Mantis」(第 8 章),階段自動到「RD 處理中」並通知 RD;RD 在 Mantis 把單解決 / 關閉、同步回來後,案件自動回到「FAE 評估」,通知 FAE 回報結果。

### 4.2 送修與維修進度

維修案件的案件頁多一塊「**送修與維修進度**」:送修方式(郵寄 / 客戶自送)、物流單號、送出與收件日期、配件清點(收到哪些配件、有沒有缺或壞)、現場更換、開始維修與維修完成日期。階段往前推進時,對應的日期沒填會自動帶今天。維修完成時會提醒 Sales 結案並填維修日報(用「工時」登記,第 12 章)。

### 4.3 簽核

有三種申請,都在案件頁的「簽核」區送出:

- **結案簽核**:問題案件在「FAE 評估」或「待 Sales 判斷」、維修案件在「維修完成」時申請,可以選結案後是暫時解決(TC)或永久解決(PC)。送出後案件進到「結案簽核中」,**核准**就結案並鎖定,**退回**或**撤回**回到申請前的階段。已連到 Mantis 且設定開了「狀態」寫回的案件,核准時會先把狀態寫回 Mantis,Mantis 拒絕就不核准。
- **轉維修簽核**:問題案件在「FAE 評估」或「待 Sales 判斷」申請轉成維修;核准後案件變成維修(案號不變),階段到「運送中」。
- **外勤簽核**:FAE 要出外勤,寫明地點與事由;核准後記在時間軸,階段不變。

簽核人依**案件負責人的主管鏈**(組織架構圖):系統設定可以選要幾階(預設 1 階 = 直屬主管),各階同時送審,**都核准才算核准,任一階退回就是退回**(退回要填原因)。

- 負責人沒有主管時,由 ISSUE TRACKER 管理者簽。
- 申請人自己就是某一階主管時,那一階視為已簽;自己不能簽自己的申請(系統管理員例外)。
- 副主管(組織架構圖上設為可代簽的人)可以代簽。
- 一件案件同一時間只能有一張進行中的簽核;申請人或管理者可以**撤回**。

簽核人在側邊欄「**待我簽核**」處理:頁面分成「等我簽核」「我送出的」「最近處理完的」,每一張可以填意見後按「核准」或「退回」。

### 4.4 通知

站內通知一定發(類型「ISSUE TRACKER 客服維修流程」,每個人可以在通知偏好關掉),email 要系統管理員在設定打開「流程通知也寄 email」(4.5)。誰會收到:

- 新案件通報:FAE(地區有指定 FAE 就只通知他們)與管理者
- 進到某個階段:那個階段輪到的角色與案件負責人;寄出 / 收件時 Sales、FAE、回報人都知道;維修完成通知 Sales 與回報人
- 建 Mantis 請 RD 協助:RD;RD 在 Mantis 有回應:FAE、負責人、回報人
- 轉維修:FAE、Sales、負責人、管理者
- 送簽核:簽核人(含副主管);核准或退回:申請人與負責人
- 結案:負責人、回報人、管理者
- **卡關提醒**:案件在同一個階段超過 N 個工作天沒有進展(預設 3 天,設 0 關閉),提醒該階段的角色、負責人與管理者,同一階段只提醒一次

做事的人自己不會收到自己那一筆的通知。

### 4.5 流程設定【管理者】

ISSUE TRACKER 設定頁(10.1)的「客服維修流程」卡片:

- **卡關提醒天數**:同一階段超過幾個工作天沒進展就提醒(0 = 不提醒)。
- **流程通知也寄 email**:需要伺服器已設定 SMTP;每個人也可以在自己的通知偏好關掉。
- **案件簽核需要幾階主管同意**:1 到 5 階,依負責人的主管鏈。
- **各地區負責的 FAE**:新案件通報時,案件的地區有指定 FAE 就只通知他們;沒指定的地區通知全部 FAE。要先有人被設成 FAE 流程角色才選得到。

**舊案件**第一次升級時,階段依狀態推算:已鎖定或不適用 = 已結案;已暫時 / 永久解決 = 待 Sales 判斷(問題)/ 維修完成(維修);處理中 = FAE 評估(問題)/ 維修中(維修)。

## 5. 處理天數與花費工時

處理天數 = 發生日期到結案日期(含頭尾),由系統自動算,沒有結案日期的案件顯示「已開 N 天」。算**工作天**(排除週六日與系統設定裡的公司假日)或**日曆天**,由管理者在 ISSUE TRACKER 設定頁選一個(10.1),套用到列表、案件頁與統整頁。

**花費工時**:處理天數是「從發生到結案隔了幾天」,**花費工時**是「實際投入了幾小時」,兩個是不同的數字。案件頁有一塊「花費工時」,列出連到這個案件的工時與合計,並能直接登記一筆(日期、小時、做了什麼);也可以在「工時」頁(第 12 章)登記時,把類別選成「案件處理」(或其他管理者開了「可連結案件」的類別),再選這個案件。這些是**非專案工時**,登記即生效、不用主管核准。管理者與案件的負責人看得到所有人登記在案件上的工時,其他人只看得到自己登記的。各產品統整頁的「花費工時合計」與「有登記工時的案件平均每案幾小時」就是由這些加總。

## 6. 結案、確認完成與鎖定

一般的結案走**結案簽核**(4.3):簽核通過,案件狀態設成暫時 / 永久解決、補上結案日期、階段變「已結案」,並**鎖定**——回報人不能再改;負責的處理人還能補時間軸、上傳附件;只有管理者能改內容或「解除鎖定」。簽核取代了原本「回報人按確認完成」,避免處理人自己宣告完成就結案。

**管理者**另外保留「確認完成」按鈕(案件已是暫時 / 永久解決時,不經簽核直接鎖定),給特殊情況用。解除鎖定後,案件回到結案前的階段。

## 7. 案件列表與各產品統整

- **案件列表**:搜尋(案件編號、客戶、QR code、描述、時間軸內容)與篩選(狀態、類型、優先級、產品、客戶、問題類型、處理單位、負責人、待指派、我的案件、**流程階段**、是否連到 Mantis、發生日期區間);篩選條件寫在網址上,可以分享。每一列的狀態下面標著目前的流程階段;連到 Mantis 的案件有「M#單號」標記。「我的案件」是你回報或你負責的。
- **各產品統整**:依發生日期區間,看每個產品(與全部)的案件數、處理中 / 暫時解決 / 永久解決、RMA 件數、平均與中位處理天數(MTTR)、平均首次回覆時間;**最常發生的問題類型**、問題大類、**零件更換排行**(次數、佔比、累計佔比)、保固狀態、案件最多的客戶、每月案件數;另外有最近 7 天、7–14 天、30 天內的案件、以及近 30 天仍在處理中與已解決的清單。這些對應原 Sheet 的 Data Sheet、Repair Parts 與 Dashboard 分頁。

## 8. Mantis 聯結

ISSUE TRACKER 可以跟 MantisBT 聯結:Mantis 的單同步成案件、案件建立到 Mantis(請 RD 協助)、連結既有的單、修改寫回 Mantis。

**連線【系統管理員】**:ISSUE TRACKER 設定(10.1)的「Mantis 連線」卡片:輸入 Mantis 網址與 API token(token 加密存放、不會顯示,留白就是沿用已存的)→「讀取 Mantis 專案」→ 選一個專案(建議用 ISSUE TRACKER 專用的專案)→「儲存並同步」。一個 ISSUE TRACKER 一個連線。

**Mantis → 案件(同步進來)**:Mantis 專案裡的單同步成案件(每 15 分鐘一次,也可以按「立即同步」),案件上會出現「Mantis #單號」連結:
- Mantis 摘要 → 問題描述;說明(加最近幾則備註)→ 規格與行為;狀態 → 狀態(預設:已解決 = 暫時解決 TC、已關閉 = 永久解決 PC、其他 = 處理中);處理人 → 負責人(用 Email、名稱比對本系統使用者,對不上可以在「負責人對應」手動指定);嚴重度 → 優先級(預設:當機與阻擋 P0、重大 P1、次要 P2、輕微 / 文字 / 建議 P3);建立時間 → 發生日期。
- Mantis 沒有的欄位(客戶、產品型號、地區、問題類型、更換零件、工時…)只在 ISSUE TRACKER 填,同步不會動它們。
- 同步進來的案件沒有客戶與產品型號,存檔前要先補(表單必填)。
- 案件列表有「Mantis」篩選(已連到 / 沒連),列上有「M#單號」標記。

**案件 → Mantis**(只有管理者與負責的處理人):
- **建立到 Mantis**:案件頁的「Mantis」區塊按「建立到 Mantis」,或新增案件時勾「同時建立到 Mantis」。Mantis 建立問題單一定要有分類,所以要先在「欄位對應與寫回」設定**預設分類**(也可以依產品型號指定不同分類)。建立後案件記下單號並顯示連結;案件目前的狀態與負責人會一併補到 Mantis 上。問題案件還在「已通報」或「FAE 評估」時,階段會自動到「RD 處理中」(4.1)。
- **連結既有 Mantis 單**:輸入單號就把案件連到 Mantis 上已經存在的單(必須在設定的 Mantis 專案裡、而且還沒連到別的案件);不會改兩邊的內容。
- **寫回**:已連到 Mantis 的案件存檔時,依「欄位對應與寫回」的設定把狀態、負責人、優先級(Mantis 嚴重度)、問題描述與規格寫回 Mantis(**預設關閉**,要在設定頁開啟並勾選哪幾類)。寫回前如果 Mantis 上那一筆被別人改過,這次不寫回也不存,請先按「立即同步這筆」;Mantis 拒絕時整筆不存並顯示原因。沒開寫回的那一類欄位,連到 Mantis 的案件在這裡是停用的(請到 Mantis 改)。
- 狀態反過來寫回:暫時解決 → Mantis 已解決、永久解決 → 已關閉、處理中 → 已指派(都可以在設定頁改,「不適用 NA」不寫回)。
- 時間軸、工時、附件不會寫到 Mantis。案件被刪除也不會刪 Mantis 上的單。

**刪除連線**:已連結的案件保留成一般案件(Mantis 連結清除),不再同步與寫回。

## 9. 選項管理與 Excel 匯入

只有**管理者**看得到側邊欄的「選項管理 / 匯入」。選項管理對應原 Sheet 的 `_mgt` 分頁:客戶(可設預設地區與客戶型態)、產品型號、地區、客戶型態、保固狀態、問題類型、更換零件(可設簡稱,統整頁用簡稱歸類)、處理單位。**用過的選項只能停用**(停用後新案件的下拉看不到,舊案件照常顯示),沒被用過的才能刪除。

**從 Excel 匯入**:選擇原 Sheet 匯出的 .xlsx(2024、2025、2026 三種版面都吃,一個檔案裡有幾個案件分頁都會讀,Dashboard、Reliability 這類非案件分頁自動略過),系統先**預覽**:幾筆可匯入、哪幾列有問題(日期沒有年份、狀態不是 Open / PC / TC / NA…)、會自動新增哪些選項;確認後才寫入。檔案裡的案件編號沿用(已經存在的略過,所以重複匯入同一份檔案不會產生重複案件),沒有編號的重新產生。

## 10. 系統設定

側邊欄「系統設定」群組。

### 10.1 ISSUE TRACKER 設定【管理者】

`/issues/settings`。ISSUE TRACKER 的管理者可以改專屬設定:

- **處理天數**算工作天或日曆天(第 5 章)。
- **案件指派時要不要另外寄 email**(需要 SMTP;關掉就只發站內通知)。
- **客服維修流程**卡片:卡關提醒天數、流程通知寄 email、簽核階數、各地區的 FAE(4.5)。

【系統管理員】在同一頁還有:**Mantis 連線**(第 8 章),以及**兩個系統共用**的設定——Email 通知總開關與通知類型、國定假日、工時類別(含「可連結案件」)、公司組織單位。這些在專案管理系統的「系統設定」裡是同一份。甘特圖、週報、BOM、預算這類專案管理專屬的設定不在這裡。

## 11. 使用者管理與組織架構圖

### 11.1 使用者管理【系統管理員】

側邊欄「系統設定 → 使用者管理」(`/issues/users`),跟專案管理系統是**同一批使用者**。編輯使用者時可以設定:

- **可以使用的系統**:專案管理系統(勾選)與 ISSUE TRACKER 的**權限角色**(不可進入 / 回報人 / 處理人 / 管理者)。系統管理員兩個系統都能進,在 ISSUE TRACKER 裡等同管理者。新增的使用者預設只能進專案管理系統。
- **客服維修流程角色**:Sales / FAE / RD,可複選(選了 ISSUE TRACKER 角色才會出現)。
- 姓名、Email、登入角色、所屬主管;另可重設密碼、解除鎖定、刪除(無法復原)。「所屬主管」決定誰簽核這個人經手案件的簽核(4.3);已經掛在組織架構圖上的人,所屬主管由架構圖決定、在這裡鎖住。

使用者頁還有「休假」「資源」分頁、工作交接、工時免審核等專案管理系統的功能,細節請看專案管理系統的使用手冊。

### 11.2 組織架構圖

側邊欄「系統設定 → 組織架構圖」(`/issues/org-chart`),大家可看、系統管理員可改,同一棵組織樹。每個部門有一位**主管**、底下掛著成員;有了這張圖,就知道誰是誰的直屬(一階)、二階、三階……主管。

- 點部門卡片選取;**查主管階層**(所有人都能用)選任何一個人,列出他頭上的直屬、二階、三階……主管。
- 【系統管理員】選取部門後,可以改名、設主管、換上層部門、調順序、加入或移出成員、新增 / 刪除部門;可以在主管之外加**副主管**(可代主管簽核),或自己填職稱的其它職能(勾「可代簽」才能代簽)。也可以用滑鼠把部門卡片拖到別的部門旁邊(同一層排序)或中間(變成它的下層)。
- 簽核人就是用這張圖算:案件負責人的直屬主管是第 1 階、他的主管是第 2 階……(4.3)。修改架構圖後,所有人的所屬主管會一併更新。

## 12. 工時

側邊欄「工時」(`/issues/timesheet`)。跟專案管理系統是**同一套工時**,一週一個畫面的行事曆:

- 在空白處點一下(排一小時)或拖出一段時間來新增;點一筆編輯或刪除;拖曳整塊換時間或換天;拖下緣改時數(15 分鐘為單位)。一天合計不能超過 24 小時;右上角是本週合計。
- 登記表單可以選類別。**案件處理**類別(或其他管理者開了「可連結案件」的類別)會多一個「連結 ISSUE TRACKER 案件」欄位,這筆工時就算在那個案件的花費工時上(第 5 章)。維修完成後要填的「維修日報」也用這裡登記。
- 非專案的工時(案件處理、會議…)登記即生效;專案工作項的工時要主管核准(這是專案管理系統的功能)。
- 另有「統計」分頁、範本與複製上週、從 Google 日曆匯入、重複登記(例行會議)等功能,細節請看專案管理系統的使用手冊。

## 13. 說明、問題回報與這份手冊

ISSUE TRACKER 的每個畫面右下角都有藍色圓形的「**?**」:

- 第一個按鈕開這份手冊裡**你現在這個畫面**對應的章節——案件列表、回報新案件、案件頁、流程進度條、簽核、各產品統整、選項管理與匯入、各個設定頁都有對應的小節。
- 也可以在這裡搜尋手冊、**選取畫面上的元素**來查手冊,或把遇到的問題寫下來送出。登入後的「選擇要進入的系統」頁與「尚未被授權」頁也有這個按鈕。
- 寫下來的問題都送到系統管理員的「**使用者回報**」頁(`/issues/feedback`,有未處理數的徽章),每一則會標明是從專案管理系統、ISSUE TRACKER,還是登入 / 選系統頁送的。管理者處理後可以標為已處理並留說明。回報不會寄信通知。

**這份手冊**:側邊欄「使用手冊」。左邊是目錄與搜尋(至少兩個字,結果會列出出現在哪幾章、前後文),右邊是內容,網址的 `#` 後面是章節,可以直接分享連結。
