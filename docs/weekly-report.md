# 週報

每週一份,自動產、自動寄、自動存檔,系統裡也看得到。

## 為什麼是「推」不是「撈」

原本想的是讓 Claude 從外面連進來撈資料。那條路要把伺服器開到公網(網域、憑證、防火牆、金鑰外流的風險),而週報是排程產物、不是互動查詢 —— 伺服器自己算完送出去,**一個洞都不用開**。

要互動追問再走 MCP 連接器那條路,見 [mcp-connector.md](mcp-connector.md)。兩條路不衝突,週報這條先能用。

## 產出去哪裡

一次跑完會同時做三件事:

1. **存進資料庫** —— 側邊欄「週報」那一頁看得到,可以翻歷史、下載 Markdown
2. **寫成檔案** —— 落在專案底下的 `weekly-reports/`,一份 `.md` 一份 `.json`
3. **寄到你的信箱** —— 用系統既有的 SMTP 設定,**一個專案一封**,標題「專案名稱週報 W41 (起 ~ 迄)」,內容只有那個專案的部分

三件事各自回報結果。**寄不出去會明講寄不出去**,不會回一句「已產生」讓你以為信寄了。

## 排程設定(Windows 工作排程器)

### 一、產一把金鑰

**系統設定 → 整合 → 新增 API 金鑰**,用你自己的帳號產。

金鑰借用發它那個人的權限,所以週報涵蓋的看板範圍 = 你登入時看得到的範圍。金鑰只顯示一次。

### 二、把金鑰放進環境變數

開一個命令提示字元:

```bash
setx HRAPP_API_KEY "hrapp_剛剛抄下來的金鑰"
```

放環境變數而不是寫進檔案:`scripts\weekly-report.cmd` 會進版控,而排程器的工作內容在介面上點開就看得到。

### 三、建立排程

工作排程器 → 建立基本工作:

| 欄位 | 填什麼 |
|---|---|
| 名稱 | 週報 |
| 觸發程序 | 每週,星期一,08:00 |
| 動作 | 啟動程式 |
| 程式 | `C:\Users\Stanley.Huang\Desktop\人力資源管控程式\scripts\weekly-report.cmd` |
| 起始於 | `C:\Users\Stanley.Huang\Desktop\人力資源管控程式` |

勾「不論使用者登入與否均執行」,這樣沒登入 Windows 也會跑。

### 四、先手動試一次

在排程器上對它按「執行」,然後看信箱跟 `weekly-reports/` 資料夾。

## 端點

```
POST /api/reports/weekly?week=last&deliver=1
Authorization: Bearer hrapp_...
```

| 參數 | 值 | 預設 |
|---|---|---|
| `week` | `last`(最近一個已結束的範圍)、`this`(現在所在的範圍),或 `YYYY-MM-DD`(那一天所在的範圍) | `last` |
| `deliver` | `1` 寄信與存檔,`0` 只算不送 | `1` |

也吃瀏覽器的登入狀態 —— 週報頁面上那兩顆按鈕打的就是同一支。

**範圍**不一定是週一到週日:系統設定「專案週報排程」裡的「週報涵蓋的範圍」決定從星期幾到星期幾(預設週三到週二),手動產生與排程寄的都照它。回應裡的 `delivery.mail.messages` 是每個專案那一封信的結果。

`GET` 同一個網址會回一段自我描述,不需要金鑰,用來確認端點活著。

## 「這週完成了什麼」是怎麼算出來的

**拿這一週跟上一週那一份存檔比出來的**,不是去解析活動紀錄裡那幾句中文再猜。

- 這週在已完成、上週不在 → 這週完成的
- 這週逾期、上週不逾期 → 新逾期
- 上週逾期、這週既不逾期也沒完成 → 脫離逾期

**做完的不算「脫離逾期」** —— 它不是趕上了,是做完了,已經在完成那一欄,再數一次會是同一件事被記兩遍。

第一次跑沒有上一週可比,那份週報會直接說「這是第一份週報」,而不是列一排 0 假裝這週什麼都沒發生。

逾期與七天內到期是**產出當下的快照**,標題也這樣寫 —— 跟「這一週發生了什麼」混在一起講,讀的人會把快照當成本週新增。

## 一個人一份

看得到哪些看板是跟著人走的,所以週報也是。同一個人同一週重跑會覆蓋,不會長出第二份。

要多個人各自收到自己的週報,就各自產一把金鑰、各自排一個工作。

## 數字從哪來

全部走畫面在用的那些函式:`computeOverdueUpcoming`、`computeStatusBuckets`、`analyzeDelays`、`summarizeBudget`。週報跟儀表板對不起來的時候,沒有人會知道該信哪一個。

## 檔案放哪、為什麼不放 `public/uploads`

`weekly-reports/` 是 docker-compose 掛進容器的一個資料夾,用檔案總管直接打得開,而且已經在 `.gitignore` 裡 —— 裡面有預算與人力,不該進版控。

沒有放在 `public/uploads` 底下,因為那個目錄是對外服務的:週報不該靠一個難猜的網址當作保護。

要換地方就設 `WEEKLY_REPORT_DIR`,並且記得同步改 `docker-compose.yml` 的掛載。
